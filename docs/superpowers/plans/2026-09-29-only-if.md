# `onlyIf` Conditional Task Execution — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `onlyIf` task configuration field — a predicate evaluated in the worker that skips a single task's body without altering the task graph.

**Architecture:** `onlyIf` is resolved inside `runTask` (`engine/worker.ts`) after the working directory and task options are resolved and **before** cache validation. A falsey result sends a new `"skipped"` worker message and returns, so the task performs no cache work and never enters `Running`. `TaskPool` maps that message to a new `onTaskSkipped` event, which flows through `EventEmitter` → `ExecutionTracker` (new `TaskStatus.Skipped`) → reporters and the plugin `afterTask` hook.

**Tech Stack:** TypeScript (ESM, strict, `node22`), vitest (integration-first, `withGeneratedFixture` + `execa`), tsgo/tsup builds, api-extractor for the public API surface.

**Spec:** `docs/superpowers/specs/2026-09-29-only-if-design.md`

## Review Focus

Input classes the spec implies but which no single task's happy path exercises. Each has a test assigned to the task that owns the code.

1. **A non-boolean return value** (`onlyIf: () => "" `, `() => 0`, `() => undefined`). The spec says "resolves false → skipped", but JS predicates return whatever the author wrote. Truthiness must be applied consistently, not `=== false`. Test in Task 3.
2. **A rejected promise, not just a thrown error.** An `async` predicate that rejects must fail the task identically to a synchronous throw. Test in Task 3.
3. **A skipped task whose dependents read `dependencyFingerprints`.** A skipped task produces no outputs fingerprint; a cacheable dependent must still compute a stable key rather than crash on a missing entry. Test in Task 6.
4. **A skipped task that also declares `inputs`/`outputs`.** The skip must win over cacheability — no fingerprint computed, no cache entry written, and a later un-skipped run must not see a poisoned cache. Test in Task 6.
5. **A skipped task under `--parallel` with `maxWorkers: 1` (inline executor).** The inline path invokes the notifier in-process rather than across a MessagePort; the skip must settle identically on both executor paths. Test in Task 6.

Insert after the "Timeouts and Retries" section:

```markdown
## Conditional Execution

A task may declare `onlyIf`, a predicate deciding whether the task's body runs. The
predicate receives the same run context passed to the task body and may resolve
synchronously or asynchronously.

- When `onlyIf` is omitted, or resolves to a **truthy** value, the task executes normally.
- When it resolves to a **falsey** value, the task is **skipped**: its body does not run and
  the task settles with the Skipped status (see [01-task.md](01-task.md)).

The predicate is evaluated **at execution time**, after the task's configuration, options,
and working directory are resolved, and **before cache validation**. Consequences:

- The predicate may observe state produced by the task's dependencies, which have already
  completed by the time it runs.
- A skipped task performs no cache work: no fingerprint is computed, no outputs are
  restored, and no cache entry is written. This holds even when the task declares inputs
  and outputs.
- A skipped task contributes no outputs fingerprint to its dependents.

Skipping affects only the task itself. Its dependencies have already run, and its dependents
still run, treating the skipped task as satisfied. Skipping never removes tasks from the
graph — that is the role of exclusion (see [03-scheduling.md](03-scheduling.md)).

A predicate that throws, or whose returned promise rejects, fails the task exactly as a
failing task body does. `timeout` and `retries` bound the task function only; they do not
apply to the predicate, which is evaluated once.
```

const RAW = Symbol("raw");

export interface RawExpression {
	readonly [RAW]: string;
}

/** Marks a config value to be emitted verbatim rather than JSON-serialized. */
export function raw(source: string): RawExpression {
	return { [RAW]: source };
}

function isRaw(value: unknown): value is RawExpression {
	return typeof value === "object" && value !== null && RAW in value;
}
```

/** Serialize config options to inner object-literal text, emitting raw values verbatim. */

}

## Summary

Adds a Gradle-style `onlyIf` task configuration field: a predicate evaluated at execution
time that skips a single task's body without altering the task graph.

```ts
tasks.register("publish", {
	dependsOn: ["build"],
	onlyIf: () => process.env.CI === "true",
	run: async () => { /* ... */ }
});
```

## Behavior

- Evaluated in the worker after config/options/workingDir resolution and **before** cache
  validation, so the predicate can observe what dependencies produced, and a skipped task
  does no cache work at all.
- Skipping affects only that task: dependencies have already run, dependents still run.
  This is `onlyIf`, not `--exclude` — the graph is unchanged.
- A throwing or rejecting predicate fails the task. `timeout`/`retries` do not apply to it.

## Notable

- New `Skipped` task status, `"skipped"` worker message, and `onTaskSkipped` event.
- `afterTask` fires for skipped tasks (as it does for cache hits); `beforeTask` does not.
- The run summary's existing count of tasks that never ran after an upstream failure is
  reworded from "skipped" to "not run", so "skipped" unambiguously means `onlyIf`.
